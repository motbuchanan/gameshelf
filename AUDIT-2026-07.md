## 2. Bugs found → FIXED in this bundle (deploy = v34)

**Fix 1 — Chess TV mode was unreachable** (`chess.html`, 1 line)
The shelf toggle writes `shelf_tv = "1"`; chess alone read `gn_tv === "on"`. Chess's
TV mode could never activate. CLAUDE.md suspected this at v27; confirmed live and fixed —
chess now reads `shelf_tv === "1"` like checkers/backgammon/chinese/sorry.
> If your repo's chess.html is newer than this zip: apply the one-liner there instead —
> line ~544, `const TVMODE=localStorage.getItem("shelf_tv")==="1";`

**Fix 2 — 8 record keys missing from GAME_KEYS** (`gamenight.js`, 1 edit)
`snakearcade, brickbreak, blocks, stardefender, minesweeper, gemmatch, craps, liarsdice`
recorded games but weren't in `GAME_KEYS`. Day-to-day sync still worked (recordGame
mirrors per-key, and the subscribe listens to the whole records collection), but:
- **First-seed skipped them** — a device's pre-sync arcade history never got pushed up.
- **resetCloud skipped them** — worse, a household reset left the arcade docs alive in
  Firestore, and the collection-wide onSnapshot immediately pushed the "reset" records
  back onto every device. Reset didn't reset.
GAME_KEYS is now 44 entries, duplicate-checked.

**Fix 3 — Scrabble invisible to achievements** (`achievements.js`, 1 line)
`scrabble_games` was absent from the NAMES map, so Scrabble plays earned no per-game
badge ladder (they only counted toward totals). Added.

**Deploy set (5 files):** `chess.html, gamenight.js, achievements.js, index.html (badge v34), sw.js (gameshelf-v34)`.
chess.html and achievements.js came from session-baseline copies — if a parallel chat
touched either, apply the one-line edits to the repo version instead of overwriting.

## 4. Cross-device multiplayer — the real answer

**The infrastructure already exists and is proven.** `GN.room` in the runtime is a
complete Firestore-backed online layer: `create / join / watch / pushState / start /
presence`, 4-letter room codes, rejoin-by-code after app close, mock-testable. Trouble
ships it in production ("🌐 Play online") — the integration cost was **~137 lines**.

The pattern per game: `snapState()/loadState()` serializers, an Online button that
routes into create/join, a turn gate (`my turn → play + pushState; else render what
arrives`). Randomness travels inside state, so dice games work.

**Rollout order (easiest → hardest), all perfect-information turn games:**
1. **Connect 4** — tiny state (42 cells + turn). Proves the template port.
2. **Gomoku / Hex / UTTT** — same shape: grid + turn.
3. **Checkers / Reversi / Morris** — grid + a little phase state.
4. **Dots & Boxes / Mancala / Ur** — small structured state, dice already solved.
5. **Chess** — bigger state (castling/EP/clock fields), still the same pattern.
6. **Battleship** — first hidden-information game; needs per-seat secret state
   (each device holds its own fleet locally, only shots travel). Good bridge to:
7. **Card games (One Card Left!, Go Fish, Gin)** — hidden hands are actually a
   *better* fit for two devices than pass-and-play (no curtains needed — each screen
   just shows its own hand), but each needs a per-seat view and a dealt-state
   authority model. Real design work; do after the board-game wave.

Each of tiers 1–5 is roughly a Trouble-sized session or smaller. Recommend shipping
Connect 4 online as the next chunk whenever momentum returns — it's the template
everything else copies.

**Server-side notes (can't verify from the zip — check when convenient):**
- Firestore security rules must cover `rooms/{code}` (Trouble online working in prod
  implies they do, but confirm the rule isn't wide open beyond authed users).
- Rooms are never deleted — they accumulate in Firestore forever. Harmless at family
  scale; a TTL cleanup (or delete-on-finish in `pushState` when status="over") is a
  someday-nicety, not urgent.

## 7. Confidence map — what this audit could and couldn't see

**High confidence** (mechanically verified today): everything in §1 and §2.

**Attested by past harnesses, not re-run today**: chess engine (perft 17/17), mancala
bot parity (80k positions), OCL engine (~8,500 games, conservation invariant),
checkers/reversi bots, sudoku generator double-validation, wordsearch findability.
These were rigorously validated when built; the files parse identically now.

**Lowest confidence — flagging honestly:**
1. **The post-log games' logic**: gin (knock/undercut scoring), blackjack (payouts,
   double-down edge cases), solitaire (move legality, recycle rules), liar's dice
   odds, craps point logic, memory/match3/minesweeper win states, and the puzzle
   books besides sudoku/wordsearch. They were added after CLAUDE.md's log went quiet,
   so I have **no validation record** for them — syntax and wiring are verified,
   gameplay correctness is not. Six testers poking the shelf is currently the only
   test harness these games have. If any game deserves a validation session before
   dormancy, it's **gin** (the most scoring-rule-dense of the group).
2. **Anything runtime**: this was a static audit — no browser. Rendering, touch,
   audio, and live Firebase behavior are attested by structure + history, not execution.
3. **The server side**: Firestore rules, prod data shape, whether tester-created
   households have polluted anything. Invisible from the zip.
4. **index.html itself**: 172 KB of hand-spliced arrays with a documented history of
   biting during edits. It verified clean today, but it's the file most likely to
   break during a future casual edit. Treat index splices as surgery, always.
